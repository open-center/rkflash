# 后端详解：`rkflash-backend`

后端采用六边形（端口-适配器）架构，分三层：

```text
application/      门面 FlashApplication + 用例规则 + 端口（trait）定义
domain/           后端内部执行计划与扇区校验（不访问任何系统资源）
infrastructure/   process / persistence / rockchip 三组具体适配器
```

核心思想：**所有系统能力（进程、文件、厂商工具）经应用端口注入**。`FlashApplication`
只协调端口，不调用 `std::fs`、`std::process` 或 Rockchip 模块；执行计划
（`ExecutionPlan` / `CommandSpec`）与适配器类型全部 `pub(crate)`，不暴露给前端。

[lib.rs](../app/backend/src/lib.rs) 是组装根，`create_application()` 的装配流程：

1. `protocol: Arc<dyn ToolProtocol> = Arc::new(UpgradeToolAdapter::default())`
   ——协议解析在后台线程运行，需要 `Arc + Send + Sync`；
2. `planner`、`profile` 各 `Rc::new(UpgradeToolAdapter::default())`
   ——计划与分区表只在 UI 线程使用，适配器无状态；
3. `runtime = Rc::new(ProcessRuntime::new(discover_upgrade_tool(), protocol, "upgrade_tool/log"))`；
4. `FlashApplication::new(ApplicationPorts { executor: runtime.clone(), device_monitor: runtime.clone(),
   tool_locator: runtime.clone(), operation_log: runtime, planner, profile,
   workspace_repository: Box::new(JsonConfigurationRepository), file_system: Box::new(LocalFileSystem) })`。

即端口-适配器映射：

| 端口 | 适配器 |
|---|---|
| `OperationExecutor` / `DeviceMonitor` / `ToolLocator` / `OperationLog` | `ProcessRuntime`（一个对象实现四端口，`Rc` 共享） |
| `FlashPlanner` / `FlashProfile` / `ToolProtocol` | `UpgradeToolAdapter` |
| `WorkspaceRepository` | `JsonConfigurationRepository` |
| `FileSystem` | `LocalFileSystem` |

## 1. domain 层

### 1.1 执行计划：[execution.rs](../app/backend/src/domain/execution.rs)

| 类型 | 字段 | 说明 |
|---|---|---|
| `CommandSpec` | `label: String`, `args: Vec<OsString>` | 一条外部命令；label 为中文步骤名；用 `OsString` 保留非 UTF-8 路径 |
| `ExecutionPlan` | `name: String`, `commands: Vec<CommandSpec>` | 一次任务的命令序列；`ExecutionPlan::single` 为单命令构造器 |

### 1.2 扇区校验：[sector.rs](../app/backend/src/domain/sector.rs)

`normalize_sector(value: &str) -> Result<String, String>`：

1. 去首尾空白；
2. `0x` / `0X` 开头按十六进制解析，否则按十进制 `u64` 解析；
3. 成功返回 **trim 后的原文**（保留用户输入的进制形式）；
4. 失败返回 `"必须是十进制数或 0x 开头的十六进制数：{trimmed}"`。

设计意图（安全关键）：**破坏性读写命令（WL/RL/EL）的扇区参数必须先经过这里**，
既拒绝非法输入，也保证工具收到的是校验过的规范文本而不是用户原始串（测试覆盖
`"8192;rm -rf /"`、`"-1"`、`"0xGG"` 等注入尝试）。该函数被 validation（校验层）与
upgrade_tool（计划构建层）**共用**，两处解析规则天然一致。

## 2. application 层

### 2.1 端口定义：[ports/](../app/backend/src/application/ports/)

按 execution / persistence / planning 三组组织，共 9 个 trait：

**执行组** [execution.rs](../app/backend/src/application/ports/execution.rs)：

| trait | 方法 | 说明 |
|---|---|---|
| `OperationExecutor` | `is_active` / `start(plan)` / `cancel` / `drain_events` | 运行、取消与收集任务事件 |
| `DeviceMonitor` | `latest_device_snapshot` | 只读发布设备快照 |
| `ToolLocator` | `tool_path` / `set_tool_path` | 读取与切换外部工具路径 |
| `OperationLog` | `tool_log_directory` / `set_tool_log_directory` / `begin_operation_log` / `finish_operation_log` / `operation_log_path` / `append_operation_log` | 工具日志目录与单次操作日志 |

**持久化组** [persistence.rs](../app/backend/src/application/ports/persistence.rs)：

| trait | 方法 | 说明 |
|---|---|---|
| `WorkspaceRepository` | `load_workspace` / `save_workspace` | 工作区配置持久化 |
| `FileSystem` | `read_text` / `list_files` / `is_file` / `is_directory` / `file_size` | 用例所需的最小文件查询能力 |

**规划组** [planning.rs](../app/backend/src/application/ports/planning.rs)：

| trait | 方法 | 线程约束 |
|---|---|---|
| `FlashPlanner` | `plan(&FlashOperation) -> ExecutionPlan` | 仅 UI 线程，不要求跨线程 |
| `FlashProfile` | `default_images` / `parse_parameter` | 仅 UI 线程 |
| `ToolProtocol` | `device_scan_command` / `parse_device_list` / `parse_progress` / `parse_failure` | 后台线程依赖，要求 `Send + Sync` |

### 2.2 门面：[facade.rs](../app/backend/src/application/facade.rs)

`FlashApplication` 持有 8 个端口 + `device_snapshot`（最近一次有效快照缓存），实现
`FlashService`。关键方法语义：

- **`poll(&mut self)`**：取设备快照，**仅当 `Some` 时更新缓存**；返回
  `ApplicationUpdate { device_snapshot, events: drain_events() }`。
- **`execute(&self, operation)`** 顺序：`validate` → 有任务在跑则报
  "已有任务正在执行" → `planner.plan` → `begin_operation_log` → `executor.start`。
  启动失败时向日志写 ERROR 级记录、结束日志，并把日志路径带回错误消息：
  `"{error}；操作日志：{log_path}"`。
- **`validate`（确认策略核心）**：
  1. 工具未配置 → "未配置烧录工具，请点击右上角"选择工具""；
  2. 设备数量**必须恰好 1 台**：0 台时若缓存快照带 `error` 则携带扫描失败原因；多台 →
     "发现 {N} 台设备。为避免误刷，要求只连接一台目标设备"；
  3. `validate_operation`（见下）。
- **`set_tool_path`**：先 `is_file` 校验再写入。
- **`import_parameter`**：读文件 → `profile.parse_parameter` → 若结果不含 `parameter`
  分区则在头部插入（地址 `0x00000000`）→ 列出 parameter 文件同目录文件 →
  `resolve_image_paths` 自动匹配镜像。
- **`load_workspace`**：`format_version != WORKSPACE_FORMAT_VERSION` 时报
  "不支持的配置版本 {v}，当前仅支持版本 1"。

### 2.3 输入校验：[validation.rs](../app/backend/src/application/validation.rs)

`validate_operation(operation, file_system)` 与工具无关，按变体分派：

| 变体 | 规则 |
|---|---|
| `DownloadImages` | 勾选项至少一项；每项文件存在；address 非空时过扇区校验 |
| `UpgradeFirmware` / `EraseFlash` | 固件文件存在 |
| `UpgradeLoader` | Loader 文件存在 |
| `ReadLba` | start/count 过扇区校验；输出路径父目录存在即可 |
| `WriteLba` | start 过校验；镜像文件存在 |
| `EraseLba` | start/count 过校验 |
| `ExportSerialLog` | 输出路径父目录存在即可 |
| `Query` / `Control` | 无额外校验 |

错误消息统一中文并携带"下载项/固件/Loader"等标签与路径上下文。

### 2.4 镜像匹配：[image_resolution.rs](../app/backend/src/application/image_resolution.rs)

`resolve_image_paths(entries, parameter_path, files)` 纯匹配规则：

- 分区名取冒号前部分（`rootfs:grow` → `rootfs`）；
- `parameter` 分区（忽略大小写）直接绑定 parameter 文件路径；
- 其余按扩展名优先级 **`img` > `bin` > `txt`** 匹配同目录 `file_stem` 相同（忽略大小写）的文件；
- 扩展名匹配全部失败时退化为整文件名精确匹配；
- 匹配成功 → 写入路径并 `enabled = true`；失败 → 清空路径、`enabled = false`。

## 3. infrastructure/process/ —— 通用进程运行时

与厂商无关的进程执行基础设施，按职责分五个文件。

### 3.1 [command.rs](../app/backend/src/infrastructure/process/command.rs) —— 进程环境

- `configure_tool_process(command, tool_path, tool_home)`：
  - `current_dir` = 工具所在目录；
  - `env("HOME", tool_home)`：**HOME 隔离**，厂商工具写 `$HOME` 的状态/日志不会污染用户家目录；
  - unix 下 `process_group(0)`：工具进程独立成组，终止时可按组清理其派生的孙进程，
    避免残留进程占用 USB 或持有输出管道。
- `terminate_tool_process(child)`：unix 下 `killpg(pgid, SIGKILL)` 按组强杀；失败退化为 `child.kill()`。
- `format_command`：把命令拼成单行展示字符串，含空白/引号的参数加引号转义
  ——**仅用于日志/UI 展示，不用于执行**。

### 3.2 [logging.rs](../app/backend/src/infrastructure/process/logging.rs) —— 日志体系

- HOME 隔离目录：`{TMPDIR}/rkflash/.runtime/{pid}-{纳秒时间戳}`，每次启动唯一。
- `purge_stale_runtime_directories`：清理历史残留的隔离目录——目录名解析出 pid，
  `kill(pid, 0)` 探测：ESRCH（进程确实不存在）才删除；EPERM 等表示进程属于其他用户
  仍存活，跳过。
- 日志目录解析：环境变量 `RKFLASH_LOG_DIR` 优先，否则 `{TMPDIR}/rkflash/log`。
- `prepare_log_redirect`：在 `{隔离HOME}/upgrade_tool/log` 位置建立
  **symlink → 用户日志目录**（先建 `log.next` 临时链接再 rename，原子替换），
  解决 upgrade_tool 把日志固定写 `$HOME/upgrade_tool/log` 的问题。
- 操作日志文件名：**`YYYYMMDD-HHMMSS-mmm.log`**（本地时间，23 字符）；同名冲突追加
  `-01`…`-99`；日志行格式 **`[YYYY-MM-DD HH:MM:SS.mmm] [LEVEL] text`**，每行写入后 flush。

### 3.3 [monitor.rs](../app/backend/src/infrastructure/process/monitor.rs) —— 设备轮询

后台线程 `spawn_device_poller` 循环执行 `LD` 扫描：

- **任务执行中不扫描**（避免查询/烧录过程中隐式切换设备模式）；
- 每轮扫描后休眠 **2 秒**（分片睡眠以便快速响应停止）；
- 单次扫描超时 **10 秒**（工具在 USB 异常时可能永久阻塞），超时按进程组终止；
- 扫描经 `command_gate` 互斥锁与任务执行串行。

### 3.4 [runtime.rs](../app/backend/src/infrastructure/process/runtime.rs) —— ProcessRuntime

整个并发的枢纽。关键字段：工具路径（`Arc<Mutex<Option<PathBuf>>>`，与轮询线程共享）、
操作日志状态（持有打开的文件句柄，**一次操作期间保持打开**）、事件通道、设备快照通道、
`active`（`AtomicBool` 任务占用）、`cancelled`、`child` 槽、`command_gate`（命令互斥锁）。

行为要点：

- **锁中毒一律恢复**（`unwrap_or_else(|p| p.into_inner())`），锁持有者 panic 不会使运行时失能。
- `start(plan)`：`compare_exchange` CAS 抢占保证**同一时刻只有一个任务**；
  未配置工具则回滚并报错；随后 `thread::spawn(run_plan)` **异步执行，立即返回**。
- `cancel()`：置取消标志 + 对子进程按组 SIGKILL。
- `set_tool_log_directory`：任务运行中禁止切换；用 `try_lock` 抢 `command_gate`
  （最多约 1 秒重试）避免扫描挂起时冻结 UI。
- `run_plan` 后台线程（任务状态机）：
  1. 拿 `command_gate` → 发 `TaskStarted`；
  2. 逐命令：检查取消 → 发 `StepStarted`（带展示用命令行）→ spawn 进程
     （HOME 隔离 + 进程组 + piped 输出）→ stdout/stderr 各起一个**读取线程**逐行清洗、
     解析进度（整体进度 = `(step_index + 步内进度) / step_count`）与文本失败；
  3. 失败判定优先级：**用户取消 > 协议文本失败（可覆盖退出码 0）> 退出码非 0**
     ——即使退出码为 0，输出含 `Fail` 等模式也判失败；
  4. 收尾顺序：**先关操作日志 → 再复位 active → 最后发 `TaskFinished`**，
     防止前端立即开始下一个任务时误关新任务的日志。
- `Drop`：停止轮询线程 → 取消任务 → 删除 HOME 隔离目录。

### 3.5 [terminal.rs](../app/backend/src/infrastructure/process/terminal.rs) —— 终端清洗

`sanitize_terminal_text`：六状态机剥离 CSI/OSC/DCS 等转义序列、剔除控制字符但保留 `\t`，
例如 `"\x1b[1A\x1b[2KDownload Image... (55%)"` → `"Download Image... (55%)"`。

## 5. infrastructure/rockchip/ —— Rockchip 特殊实现

### 5.1 [discovery.rs](../app/backend/src/infrastructure/rockchip/discovery.rs) —— 工具发现

`discover_upgrade_tool()` 按序查找，首个命中返回：

1. 环境变量 `RK_UPGRADE_TOOL`；
2. 可执行文件同目录 `tools/upgrade_tool`；
3. 可执行文件同目录 `upgrade_tool`；
4. 当前工作目录 `tools/upgrade_tool`；
5. 当前工作目录 `upgrade_tool`；
6. `/usr/lib/rkflash/upgrade_tool`（`.deb` 安装位置）；
7. `PATH` 各目录。

### 5.2 [parameter.rs](../app/backend/src/infrastructure/rockchip/parameter.rs) —— 分区参数解析

解析 `parameter.txt` 中的 `mtdparts=` 段：

1. 定位 `mtdparts=` → 取第一个 token → 剥首尾引号 → 去设备名前缀（`rk29xxnand:`）；
2. 逗号分割分区项；每项从 `( )` 中取分区名（保留 `rootfs:grow` 冒号后缀），
   `(` 之前按 `@` 分割取**起始地址**；
3. 生成 `ImageEntry`（`enabled` 初始 false，等镜像匹配后再启用）。

### 5.3 [parser.rs](../app/backend/src/infrastructure/rockchip/parser.rs) —— 输出解析

- `parse_device_list`：筛选含 `DevNo=` 的行，提取 DevNo/Vid/Pid/LocationID/Mode/SerialNo。
- `extract_progress`：找 `%` 前的数字 → ÷100 并 clamp 到 0..1。
- `extract_failure`：小写化后命中任一模式即判失败——包含 `fail`、以 `error` 开头、
  包含 ` error:`、包含 `not found any device` / `no device found`；
  `Read Flash Info Success` 不误报。这是"退出码 0 也可能失败"的文本兜底。

### 5.4 [profile.rs](../app/backend/src/infrastructure/rockchip/profile.rs) —— 分区预设

默认分区表（9 项，起始扇区十六进制）：

| 分区 | 扇区 | 分区 | 扇区 |
|---|---|---|---|
| parameter | 0x00000000 | kernel | 0x00010000 |
| uboot | 0x00004000 | boot | 0x00020000 |
| trust | 0x00006000 | recovery | 0x00040000 |
| misc | 0x00008000 | system | 0x00080000 |
| resource | 0x0000a000 | | |

快捷参数映射：`parameter→-p`、`uboot→-u`、`trust→-t`、`misc→-m`、`resource→-re`、
`kernel→-k`、`boot→-b`、`recovery→-r`、`system→-s`。
存储类型 token：`Emmc→EMMC`、`SpiNor→SPINOR`、`SpiNand→SPINAND`、`Auto→None`。

### 5.5 [upgrade_tool.rs](../app/backend/src/infrastructure/rockchip/upgrade_tool.rs) —— 命令规划

`UpgradeToolAdapter` 同时实现 `FlashPlanner` / `FlashProfile` / `ToolProtocol`。
所有扇区参数经私有 `sector_arg`（内部走 `normalize_sector`）后才下发。

**`FlashOperation` → 命令码全表**：

| 操作 | 命令序列 |
|---|---|
| 下载预设分区 | `DI <flag> <path>`（flag 查上表） |
| 下载自定义分区 | `WL <sector> <path>`（地址必填） |
| 下载后重启 | 末尾追加 `RD` |
| 升级固件 | `UF <firmware>`，`no_reset` 时追加 `-noreset` |
| 擦除 Flash | `EF <firmware>` |
| 升级 Loader | `UL <loader>` [+ `EMMC`/`SPINOR`/`SPINAND`] |
| 读取 LBA | `RL <start> <count> <output>` |
| 写入 LBA | `WL <start> <image>` |
| 擦除 LBA | `EL <start> <count>` |
| 导出串口日志 | `RCL <output>` |
| FlashId / FlashInfo / ChipInfo | `RID` / `RFI` / `RCI` |
| Capability / 分区表 | `RCB` / `PL` |
| USB 序列号（复用设备枚举）/ 安全模式 / 测试 | `LD` / `RSM` / `TD` |
| 重启 / 切换存储 / 清空序列号 / 重置 USB 管道 | `RD` / `SSD` / `SN <空参数>` / `RP` |
| 设备扫描（协议端口） | `LD` |

`runtime_log_relative_path()` 返回 `upgrade_tool/log`，ProcessRuntime 据此建 symlink 重定向。

## 6. 线程模型与协作关系

| 线程 | 职责 | 同步方式 |
|---|---|---|
| UI 线程 | facade、planner、profile、egui | `poll()` 拉取通道数据 |
| 任务执行线程 `run_plan` | 逐命令 spawn 工具进程 | `command_gate`（与扫描互斥）、`active` CAS |
| 设备轮询线程 | 周期 `LD` 扫描 | 同一把 `command_gate` |
| 每命令 2 个读取线程 | 逐行读 stdout/stderr | 事件通道汇总 |

数据流：工具输出 → 读取线程清洗/解析 → mpsc 事件通道 → `poll()` 批量拉取 →
`ExecutionEvent` 流；设备快照同理，只保留最新一条。

## 7. 安全与健壮性设计速查

- 执行前强制 validate：工具已配置 + **恰好一台设备**（多台拒绝，防误刷）+ 输入完整性；
- 破坏性命令（WL/RL/EL）扇区值**双重**经过 `normalize_sector`（校验层 + 规划层）；
- 每操作一个独立时间戳日志文件，启动失败也留痕并把日志路径返回 UI；
- 工具进程 HOME 隔离 + 独立进程组 + 按组 SIGKILL，无残留进程；
- 文本失败识别兜底退出码；Mutex 中毒一律恢复；工作区保存原子替换。

## 8. 常量与格式速查

| 项 | 值 |
|---|---|
| 扫描超时 / 扫描间隔 | 10s / 2s |
| `try_wait` 轮询间隔 | 任务 60ms，扫描 50ms |
| `set_tool_log_directory` 抢锁期限 | 约 1s（25ms 重试） |
| 操作日志文件名 | `YYYYMMDD-HHMMSS-mmm.log` |
| 日志行格式 | `[YYYY-MM-DD HH:MM:SS.mmm] [LEVEL] text` |
| HOME 隔离目录 | `{TMPDIR}/rkflash/.runtime/{pid}-{nanos}` |
| 日志 symlink | `{隔离HOME}/upgrade_tool/log → {日志目录}` |
| 工作区临时文件 | `.{pid}.{文件名}.tmp` |
| 日志目录默认 | `RKFLASH_LOG_DIR` 或 `{TMPDIR}/rkflash/log` |
