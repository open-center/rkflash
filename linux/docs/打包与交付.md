# 打包与交付详解

本文覆盖 `packaging/` 目录的全部资源、`.deb` 安装包与离线包的交付流程、以及
`upgrade_tool` 闭源二进制的完整生命周期。构建脚本本身的实现见
[构建脚本](构建脚本.md)，兼容性边界见 [兼容性说明](兼容性说明.md)。

---

## 1. 仓库结构速览

```text
packaging/
├── 71-rkflash.rules           # udev 规则（Rockchip VID 2207）
├── rkflash.desktop             # 桌面菜单入口
├── rkflash.png / rkflash.svg   # 应用图标（PNG 编译期内嵌进主程序窗口图标）
├── runtime-dependencies.txt    # 运行时依赖清单（package 与 offline 共用，单一来源）
├── upgrade_tool.sha256         # upgrade_tool 固定 SHA-256 摘要
└── THIRD_PARTY.md              # 第三方闭源二进制合规说明
```

`.deb` 安装后的文件布局：

```text
usr/bin/rkflash                                  # 主程序（release 二进制，已 strip）
usr/lib/rkflash/upgrade_tool                     # Rockchip 官方工具
usr/lib/udev/rules.d/71-rkflash.rules            # udev 规则
usr/share/applications/rkflash.desktop           # 桌面入口
usr/share/icons/hicolor/{scalable,256x256}/apps/ # 图标
usr/share/doc/rkflash/{README.md,THIRD_PARTY.md,copyright}
```

安装后可从应用菜单（Development 分类）搜索 `rkflash` 启动，或在终端直接运行 `rkflash`。

## 2. udev 规则：[71-rkflash.rules](../packaging/71-rkflash.rules)

```udev
# Rockchip devices in Maskrom / Loader mode.
# This rule must run before 73-seat-late.rules so systemd-logind can apply
# the uaccess ACL for the active desktop user.
SUBSYSTEM=="usb", ATTR{idVendor}=="2207", MODE="0660", TAG+="uaccess"
```

要点：

- **VID 匹配 Rockchip 官方 USB Vendor ID `2207`**（十六进制），覆盖 Maskrom / Loader
  两种模式；不限定 PID，因为不同芯片/模式的 PID 不同；
- `MODE="0660"` + `TAG+="uaccess"`：配合 systemd-logind 给**当前活跃桌面用户**授予
  ACL 访问——普通用户即插即用，不需要 plugdev 组或 sudo；
- 文件名前缀 `71-` 是**排序约束**：必须在 `73-seat-late.rules` 之前运行，
  否则 systemd-logind 无法应用 uaccess ACL；
- 无 GUI 的服务器场景（无活跃 seat）uaccess 不生效，需要手动配置 udev 权限或 root。

开发运行时可手动安装该规则（需重新插拔设备）：

```bash
sudo cp packaging/71-rkflash.rules /etc/udev/rules.d/
sudo udevadm control --reload-rules
sudo udevadm trigger --action=add --subsystem-match=usb --attr-match=idVendor=2207
```

安装包的 `postinst` 维护脚本会自动做同样的重载与触发（容错执行，不阻断安装）。

## 3. 桌面入口：[rkflash.desktop](../packaging/rkflash.desktop)

- 中英双语 `Name` / `Comment`，关键词覆盖 Rockchip/Flash/Firmware/Maskrom/Loader；
- `Exec=/usr/bin/rkflash`，`Icon=rkflash`；
- `StartupWMClass=rkflash` 与前端 `NativeOptions` 的 `with_app_id("rkflash")` 对齐
  ——保证 GNOME 把运行中的窗口与启动器图标正确分组（Wayland 下依赖 app_id）；
- 构建时经 `desktop-file-validate` 校验。

## 4. 运行时依赖：[runtime-dependencies.txt](../packaging/runtime-dependencies.txt)

**单一来源原则**：`build.sh` 的 `package`（写入 `.deb` control 的 Depends 字段）与
`offline`（依赖闭包求解的种子集合）共用此清单，每行一个 Debian control 表达式。

```text
libc6 (>= 2.35)          # C 运行库，对应 Ubuntu 22.04 基线
libgcc-s1
libegl1 / libgl1         # 图形栈
libx11-6 … libxrender1   # X11 系列（x11/x11-xcb/xcb/xcursor/xi/xkbcommon/xkbcommon-x11）
libwayland-client0 / libwayland-egl1   # Wayland 后端
udev                     # 设备权限与枚举
xdg-desktop-portal / xdg-desktop-portal-gtk   # rfd 文件对话框走 XDG Portal
```

窗口系统由 `eframe/winit` 的 X11、Wayland 双后端适配；代码不含针对 Ubuntu 版本号
的业务分支。

## 5. `upgrade_tool` 完整生命周期

`upgrade_tool` 是 Rockchip 的**闭源二进制**（proprietary），仓库不含其源码：

```text
来源：vicharak-in/Linux_Upgrade_Tool / Rockchip SDK / 设备厂商
  ↓ 手动放入（.gitignore 已排除该文件，不入库）
tools/upgrade_tool
  ↓ 出包时校验（packaging/upgrade_tool.sha256 + amd64 架构 + glibc 兼容性）
打包进 .deb
  ↓ 安装
/usr/lib/rkflash/upgrade_tool
  ↓ 运行时作为外部子进程调用（独立 program/argv，参数不经过 shell）
与 rkflash 主程序协作
```

- 仓库只保存 SHA-256 固定摘要 [upgrade_tool.sha256](../packaging/upgrade_tool.sha256)，
  出包前用 `sha256sum --check` 校验，防止供应链替换或损坏；
- 主程序运行时按
  `RK_UPGRADE_TOOL` 环境变量 → exe 目录 `tools/` → CWD `tools/` →
  `/usr/lib/rkflash/upgrade_tool` → `PATH` 的顺序自动发现，也可在界面右上角手动选择；
- **许可边界**：`upgrade_tool` 不在 rkflash 的 MIT 许可范围内（详见
  [THIRD_PARTY.md](../packaging/THIRD_PARTY.md)）；重新分发安装包前，发布者应自行确认
  Rockchip SDK 及设备厂商对该二进制的分发授权。

## 6. `.deb` 交付

```bash
./build.sh build          # 或 ./build.sh package（等价别名）
```

流程要点（详见 [构建脚本](构建脚本.md) §3.3）：

- **固定在 Ubuntu 22.04 基线容器**编译（glibc 2.35 为最低兼容基线），即使设置了
  `RKFLASH_UBUNTU_VERSION` 也不会改变这一基线；宿主机不参与编译和链接；
- 交付构建使用独立的 `output/target/delivery-ubuntu-22.04/`，不复用其他版本容器的
  链接缓存；
- 每次执行先**安全清空** `output/dist/`，避免旧产物混入；
- 出包前自动执行：架构边界检查、物料校验（含 upgrade_tool 摘要核对）、
  主程序与 upgrade_tool 的 ELF/glibc 门禁；
- 产出 `output/dist/rkflash_<版本>_amd64.deb` + `output/dist/install.sh`（同一安装实现）。

### 安装方式

```bash
./build.sh install        # 本机安装，不重新构建
./output/dist/install.sh # 或直接执行同目录安装器，便于两文件一起交付
```

两种入口共用 [scripts/install-deb.bash](../scripts/install-deb.bash) 的实现：
先把 `.deb` 以 `0644` 暂存到 `/var/tmp` 下的 `0755` 目录再调用 APT，完成后清理。
这样 `_apt` 可以在沙盒中正常读取安装包，**不需要放宽家目录权限**（`0750` 家目录下
直接 `sudo apt install` 会失败），也不会出现"脱离沙盒并提权"的警告。

目标机已具备全部运行依赖且明确不需要 APT 处理依赖时，也可以：

```bash
sudo dpkg --install ./output/dist/rkflash_<版本>_amd64.deb
```

`dpkg --install` 不访问软件仓库、不下载依赖；报告缺依赖时应改用匹配目标 Ubuntu
版本的完整离线包。

## 7. 离线交付包

**核心原则：应用 `.deb` 跨版本共用一份（22.04 基线构建），系统运行库必须按目标
Ubuntu 版本分别打包**——避免在 22.04 上装 24.04/26.04 的 libc、systemd 或图形栈。

```bash
./build.sh offline-all                              # 一次生成 22.04/24.04/26.04 三个包
RKFLASH_UBUNTU_VERSION=24.04 ./build.sh offline     # 只生成单个目标版本
```

每个目标版本的处理流程：

1. 复用 22.04 基线容器产出的唯一应用 `.deb`（核对 Package/Version/Architecture）；
2. 在**目标版本的容器**中以镜像内干净 dpkg 状态快照求解"干净系统所需依赖闭包"；
3. 按 APT 提供的 URL/大小/SHA-512 计划下载，双重校验后组包；
4. 产出：

```text
output/dist/rkflash_<版本>_ubuntu-<22.04|24.04|26.04>_amd64_offline.tar.gz (+ .sha256)
```

包内结构：`packages/*.deb`（应用包 + 依赖闭包）、`install.sh`（本地 `file:` 仓库
安装器）、`README.txt`、`BUILD-INFO`、`SHA256SUMS`。

### 断网实装验收

**每个离线包生成后**，脚本会在对应版本的**干净 Ubuntu 基础容器**（非构建器镜像）中
以 `--network none` 禁用网络并真实安装：

```text
两层 SHA-256 校验 → install.sh 真实安装 → dpkg 包状态检查
→ 主程序/厂商工具 test -x → udev 规则/桌面入口 test -f
```

任一环节失败，`offline`/`offline-all` 立即返回失败。不允许只验证下载数量或校验和。

### 目标机安装

```bash
tar -xzf rkflash_*_ubuntu-22.04_amd64_offline.tar.gz
cd rkflash_*_offline
sha256sum --check SHA256SUMS
./install.sh
```

安装器把包暂存到 `/var/tmp` 并组织成本地 `file:` 仓库，让 apt 自行安排安装顺序并
**保留目标机上比包内更新的版本**；软件源被完全隔离为本地仓库，不会联网下载。APT
要求目标机现有 dpkg 状态完整；存在其他半安装软件包会立即报错，但不会联网修复。

卸载同样不访问仓库：

```bash
sudo apt purge rkflash
```

卸载只清除 rkflash、桌面入口和 udev 规则；共享系统运行库会保留，避免影响其他应用。

## 8. 许可与合规

- rkflash 自身源码采用 **MIT** 许可（[LICENSE](../LICENSE)，Copyright (c) 2026 rkflash contributors）；
- 随包的 `upgrade_tool` 是 Rockchip 闭源二进制，**不在 MIT 范围内**：rkflash 不包含
  也不声称拥有其源代码，仅作为外部进程运行；分发前需确认上游授权（THIRD_PARTY.md）；
- `.gitignore` 的配套设计：`/tools/upgrade_tool`（二进制不入库）、`*.rkflash.json`
  （用户工作区配置是运行时数据）、`/output/`（构建产物）、`*.log`。
