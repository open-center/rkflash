# 契约层详解：`rktools-api` 与 `rktools-config`

本文覆盖两个最底层、被前后端共同依赖的 crate：

- [app/api](../app/api)：前后端唯一共享契约（稳定类型 + `FlashService` 能力端口）。
- [app/config](../app/config)：可序列化配置模型与 JSON 编解码。

两者的硬性边界：**不依赖 GUI、进程、文件系统、设备访问或任何具体适配器**，
依赖方向上只允许 `api → config`。构建时的架构门禁（`./build.sh architecture`）会持续检查这两条约束。

```text
rktools-frontend ──┐
                   ├──> rktools-api ──> rktools-config
rktools-backend ───┘
```

---

## 1. `rktools-api`（app/api/src/）

`lib.rs` 是 crate 门面，内部模块 `device` / `execution` / `operation` / `service` 均为私有，
统一通过 `pub use` 导出，同时 re-export `rktools-config` 的 `ImageEntry`、`WorkspaceConfig`、
`WORKSPACE_FORMAT_VERSION`。外部使用者无需感知子模块划分。

### 1.1 设备状态：[device.rs](../app/api/src/device.rs)

| 类型 | 字段 | 说明 |
|---|---|---|
| `DeviceInfo` | `number` / `vid` / `pid` / `location` / `mode` / `serial` | 依次对应 `upgrade_tool` 输出的 DevNo、Vid、Pid、LocationID、Mode（如 `Maskrom`、`Loader`）、SerialNo，全部为 `String` |
| `DeviceSnapshot` | `devices: Vec<DeviceInfo>`、`error: Option<String>` | 一轮扫描的结果；扫描失败时设备列表为空并把原因写入 `error`（互斥语义由后端保证） |

`DeviceSnapshot` 实现 `Default`，后端可用空快照作为初始状态。

### 1.2 任务事件：[execution.rs](../app/api/src/execution.rs)

前端对后端任务的**全部**可观察信息都由这两个类型表达，不暴露执行计划与适配器细节。

`ApplicationUpdate` 是 `FlashService::poll()` 的返回值：

| 字段 | 类型 | 语义 |
|---|---|---|
| `device_snapshot` | `Option<DeviceSnapshot>` | `None` 表示本轮没有新快照，前端应沿用上一次 |
| `events` | `Vec<ExecutionEvent>` | 自上次 poll 以来累积的任务事件 |

`ExecutionEvent` 五个变体构成任务完整生命周期：

| 变体 | 载荷 | 说明 |
|---|---|---|
| `TaskStarted` | `name, steps` | 任务开始，`steps` 为计划命令数 |
| `StepStarted` | `index, total, label, command` | 单条命令开始；`index` 从 1 计；`command` 为**仅用于展示**的格式化命令行 |
| `Output` | `text, stderr` | 逐行工具输出，已剥离终端控制序列 |
| `Progress` | `f32` | 0.0–1.0 整体进度 |
| `TaskFinished` | `name, success, cancelled, message` | 任务结束；`cancelled` 区分用户中止与真实失败 |

事件由后端经通道缓存，前端在每帧 `poll()` 时批量拉取，因此无需回调、无需跨线程锁。

### 1.3 类型化操作：[operation.rs](../app/api/src/operation.rs)

与工具无关的操作契约，四个枚举：

- `DeviceQuery`（`Copy`）：`FlashId`、`FlashInfo`、`ChipInfo`、`Capability`、`PartitionTable`、
  `UsbSerialNumber`（复用设备枚举命令，输出含 `SerialNo=` 字段）、`SecureMode`、`TestDevice`。
- `DeviceControl`（`Copy`）：`Reboot`、`SwitchStorage`、`ClearSerial`、`ResetUsbPipe`。
- `StorageType`（`Copy`）：`Auto`、`Emmc`、`SpiNor`、`SpiNand`。
- `FlashOperation`：10 个变体，是前端唯一能提交的操作类型。

| 变体 | 参数 | 对应功能 |
|---|---|---|
| `DownloadImages` | `images: Vec<ImageEntry>`, `reset_after: bool` | 下载镜像（分区写入） |
| `UpgradeFirmware` | `firmware: PathBuf`, `no_reset: bool` | 升级 update.img |
| `EraseFlash` | `firmware: PathBuf` | 按固件参数擦除 |
| `Query` | `query: DeviceQuery` | 只读查询类命令 |
| `Control` | `DeviceControl` | 设备控制类命令 |
| `UpgradeLoader` | `loader: PathBuf`, `storage: StorageType` | 升级 Loader |
| `ReadLba` | `start`, `count: String`, `output: PathBuf` | LBA 读取 |
| `WriteLba` | `start`, `image: PathBuf` | LBA 写入 |
| `EraseLba` | `start`, `count: String` | LBA 擦除 |
| `ExportSerialLog` | `output: PathBuf` | 导出串口日志 |

`start` / `count` 为字符串，允许十进制或 `0x` 十六进制文本；合法性由后端统一校验。

三个枚举均提供 `name() -> &'static str`，返回中文操作名（"下载镜像""读取 Flash ID""重启设备"
等），供 UI 展示与日志记录复用，避免前端再写一套映射。

### 1.4 能力端口：[service.rs](../app/api/src/service.rs)

`FlashService` 是前端调用后端的**唯一入口**，共 16 个方法，错误统一为
`Result<_, String>`（中文用户可读消息）：

```rust
fn poll(&mut self) -> ApplicationUpdate;
fn execute(&self, operation: FlashOperation) -> Result<(), String>;
fn validate(&self, operation: &FlashOperation) -> Result<(), String>;
fn cancel(&self);
fn is_active(&self) -> bool;
fn tool_path(&self) -> Option<PathBuf>;
fn set_tool_path(&self, path: PathBuf) -> Result<(), String>;
fn tool_log_directory(&self) -> PathBuf;
fn set_tool_log_directory(&self, path: PathBuf) -> Result<(), String>;
fn operation_log_path(&self) -> Option<PathBuf>;
fn append_operation_log(&self, level: &str, text: &str) -> Result<(), String>;
fn default_images(&self) -> Vec<ImageEntry>;
fn file_size(&self, path: &Path) -> Result<u64, String>;
fn import_parameter(&self, path: &Path) -> Result<Vec<ImageEntry>, String>;
fn load_workspace(&self, path: &Path) -> Result<WorkspaceConfig, String>;
fn save_workspace(&self, path: &Path, config: &WorkspaceConfig) -> Result<(), String>;
```

设计要点：

- `execute` 是**异步启动**：校验通过后立即返回，进度经 `poll()` 的事件流送达。
- `validate` 支持只校验不执行（例如 UI 在高风险操作前先给出确认文案）。
- `operation_log_path` 优先返回当前任务日志，其次返回最近一次任务的日志路径。
- 前端只面向该 trait 编程，`FlashApplication`、`ProcessRuntime`、`UpgradeToolAdapter`
  等后端具体类型对前端不可见。

## 2. `rktools-config`（app/config/src/）

### 2.1 配置模型：[model.rs](../app/config/src/model.rs)

`WORKSPACE_FORMAT_VERSION: u32 = 1`——工作区 JSON 的当前格式版本。

`ImageEntry`（可序列化）：

| 字段 | 类型 | 说明 |
|---|---|---|
| `enabled` | `bool` | 是否勾选下载 |
| `address` | `String` | 起始扇区，十进制或 `0x` 十六进制文本，**原样保存**不做规范化 |
| `name` | `String` | 分区名，可带冒号后缀（如 `rootfs:grow`） |
| `path` | `String` | 镜像文件路径；`ImageEntry::new` 构造时置空 |

注意 `path` 是 `String` 而 `FlashOperation` 中使用 `PathBuf`，转换发生在应用层。

`WorkspaceConfig`（可序列化）：

| 字段 | 类型 | 说明 |
|---|---|---|
| `format_version` | `u32` | 写入时由后端置为当前版本 |
| `images` | `Vec<ImageEntry>` | 下载镜像清单 |
| `firmware_path` | `String` | update.img 固件路径 |
| `loader_path` | `String` | MiniLoaderAll.bin 路径 |
| `reset_after_download` | `bool` | 下载完成后重启 |
| `no_reset_after_upgrade` | `bool` | 升级后不重启（对应 `-noreset`） |

### 2.2 JSON 编解码：[codec.rs](../app/config/src/codec.rs)

```rust
pub fn decode_workspace(text: &str) -> Result<WorkspaceConfig, serde_json::Error>;
pub fn encode_workspace(config: &WorkspaceConfig) -> Result<String, serde_json::Error>;
```

- `decode_workspace` 只做 `serde_json::from_str`，**不做版本检查**——版本校验由
  `FlashApplication::load_workspace` 负责，codec 保持纯编解码职责。
- `encode_workspace` 使用 `to_string_pretty`，落盘为带缩进的可读 JSON。
- 单元测试 `round_trips_workspace_configuration` 保证编码-解码往返一致。

## 3. 扩展约定

- 新增操作时：先在 `operation.rs` 增加变体并补充 `name()` 映射，再在 backend 的
  planner/validation 中实现；前端只依赖新变体，不接触命令码。
- 契约类型只增不破坏性修改；确需演进工作区格式时递增 `WORKSPACE_FORMAT_VERSION`
  并在后端加载处给出明确的中文版本错误。
