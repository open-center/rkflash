# 代码总览与文档索引

rkflash 是一个面向 Rockchip 开发板的 **Linux（Ubuntu 桌面）原生 USB 固件烧录工具**：
界面用 `egui/eframe` 构建，后端以参数数组直接调用 Rockchip 官方闭源 `upgrade_tool`
（不经过 shell），支持设备轮询、实时日志、任务进度与中止操作，对标 Windows 平台的
RKDevTool。交付形态为 `.deb` 安装包（含按 Ubuntu 版本分别打包的离线依赖包）。

本文是整套代码文档的入口；各专题文档见文末索引。

---

## 1. 仓库结构

```text
rkflashforubuntu/
├── Cargo.toml                # workspace 根（五 crate），default-members = launcher
├── rust-toolchain.toml       # 固定 Rust 工具链版本（不跟随 stable 漂移）
├── .cargo/config.toml        # target-dir 固定为 output/target
├── build.sh                  # 唯一用户构建入口（宿主/容器双路径）
├── Dockerfile                # Ubuntu 22.04 基线构建器镜像
│
├── app/                      # 全部 Rust 源码（五 crate workspace）
│   ├── api/                  # rkflash-api：前后端唯一共享契约
│   ├── config/               # rkflash-config：配置模型 + JSON codec
│   ├── backend/              # rkflash-backend：domain → application ports ← infrastructure
│   ├── frontend/             # rkflash-frontend：egui 桌面层（只依赖 api）
│   └── launcher/             # rkflash 二进制：6 行装配壳
│
├── docs/                     # 技术文档（见文末索引）
├── packaging/                # 打包资源：udev 规则、desktop、图标、依赖清单、sha256、第三方声明
├── scripts/                  # 构建脚本：config/（项目钩子）+ lib/（通用流程）
├── skills/rkflash-engineering/ # AI 工程规范（SKILL.md）
├── tools/                    # 存放外部闭源 upgrade_tool（不入库，本地准备）
└── output/                   # 全部构建产物（不入库）
```

## 2. Crate 依赖方向

```text
rkflash-launcher ──> rkflash-frontend ──> rkflash-api ──> rkflash-config
        │                                      ▲
        └────────> rkflash-backend ────────────┘
                          └────────────────────────> rkflash-config
```

| Crate | 职责 |
|---|---|
| `app/api` | 前后端唯一共享契约：类型化操作、设备状态、执行事件、配置导出和 `FlashService` 能力端口 |
| `app/config` | 镜像/工作区可序列化模型与 JSON codec |
| `app/backend` | 完整后端分层；实现 api 能力端口并装配具体适配器 |
| `app/frontend` | egui 桌面交付层；只依赖 api，提交类型化操作，不构造命令行、不启动进程 |
| `app/launcher` | 唯一二进制；只装配后端与前端，不放任何业务或 UI 实现 |

装配链：`launcher::main` → `backend::create_application()`（组装根：发现工具 →
`ProcessRuntime` → 注入 8 个端口 → 构造 `FlashApplication`）→ `frontend::desktop::run`。
前端只见 `FlashService` trait；执行计划、命令码、适配器类型全部封在后端内部。

## 3. 核心设计原则

- **端口-适配器**：所有系统能力（进程、文件、厂商工具）经应用端口注入；
  `FlashApplication` 只协调端口，不碰 `std::fs`/`std::process`；通用执行逻辑与
  Rockchip 特殊配置分离，后续替换为 Rust 原生 RockUSB 时不需要重写页面。
- **类型化操作单一契约**：GUI、确认框、校验、后端规划共享同一个 `FlashOperation`
  枚举；Rockchip 命令码的单一权威位置是
  `app/backend/src/infrastructure/rockchip/upgrade_tool.rs`。
- **安全语义**：
  - 写入/擦除/状态切换前强制确认；同一时刻只允许一个任务；**多设备拒绝执行**（防误刷）；
  - 破坏性命令（WL/RL/EL）的扇区参数双重经过 `normalize_sector` 校验；
  - 子进程参数不经过 shell；进程 HOME 隔离 + 独立进程组 + 按组 SIGKILL；
  - 不主动加载 Loader、不主动进入 Maskrom，只识别并显示当前设备模式；
  - 即使退出码为 0，也解析输出文本识别工具失败（`Fail` 等模式）。
- **构建不碰宿主**：一切构建发生在版本固定的 Docker 容器内；正式 `.deb` 固定在
  Ubuntu 22.04 基线编译（glibc 2.35 最低兼容），构建流程不调用宿主 `sudo`/`apt`/
  `cargo`/`rustup`。
- **不提交闭源二进制**：仓库只保存 `upgrade_tool` 的 SHA-256 摘要，打包时校验。

## 4. 关键运行时行为速查

| 项 | 值 |
|---|---|
| 工具发现顺序 | `RK_UPGRADE_TOOL` → exe 目录 `tools/` → CWD `tools/` → `/usr/lib/rkflash/upgrade_tool` → `PATH` → 界面手动选择 |
| 设备轮询 | 每 2 秒 `LD` 扫描，任务执行期间暂停；单次扫描 10 秒超时 |
| 刷新节奏 | 前端任务进行中 100ms / 空闲 500ms 重绘 |
| 操作日志 | 每次操作一个独立文件 `YYYYMMDD-HHMMSS-mmm.log`，默认目录 `/tmp/rkflash/log`（可用 `RKFLASH_LOG_DIR` 覆盖） |
| 工作区配置 | JSON 格式（版本 1），保存采用临时文件 + 原子 rename |
| parameter 导入 | 解析 `mtdparts=`，同目录按 `img > bin > txt` 优先级自动匹配固件 |
| 默认窗口 | 1320×860，最小 960×700，三档响应式布局 |
