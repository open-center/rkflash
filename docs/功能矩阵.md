# Windows RKDevTool 功能对照

对照基准为 Rockchip AndroidTool / RKDevTool 常见的“下载镜像、升级固件、高级功能”三页布局，
以及 `upgrade_tool` 自身公开的命令表。不同 SDK 版本和芯片可能增删命令。

| Windows 工作区 | 功能 | 当前状态 | 后端命令 / 说明 |
|---|---|---:|---|
| 下载镜像 | 标准分区镜像 | 已接通 | `DI -p/-u/-t/-m/-re/-k/-b/-r/-s` |
| 下载镜像 | 自定义地址写入 | 已接通 | `WL <BeginSec> <File>` |
| 下载镜像 | 加载 parameter | 已实现 | Rust 解析 `mtdparts=`，自动匹配同目录同名固件 |
| 下载镜像 | 设备分区表 | 已接通 | `PL` |
| 下载镜像 | 下载配置导入/导出 | 已实现 | 本项目 JSON 格式 |
| 升级固件 | 加载 / 升级 update.img | 已接通 | `UF <Firmware>` |
| 升级固件 | 升级后不重启 | 已接通 | `UF <Firmware> -noreset` |
| 升级固件 | 擦除 Flash | 已接通 | `EF <Firmware>` |
| 升级固件 | UI 内预解析固件版本 | 待原生化 | 当前由 `UF` 执行时校验并输出日志 |
| 高级功能 | Flash / Chip / Capability 信息 | 已接通 | `RID` / `RFI` / `RCI` / `RCB`；仅执行查询，不主动切换设备模式 |
| 高级功能 | 测试与重启 | 已接通 | `TD` / `RD` |
| 高级功能 | 主动切换 Loader / Maskrom | 不提供 | 由用户在设备侧完成，rkflash 只识别当前模式 |
| 高级功能 | 读取 / 写入 / 擦除 LBA | 已接通 | `RL` / `WL` / `EL` |
| 高级功能 | 升级 Loader | 已接通 | `UL`，支持 EMMC / SPINOR / SPINAND 参数 |
| 高级功能 | 序列号 / 安全模式 | 已接通 | USB 枚举序列号读取自 `LD` 的 `SerialNo`；`SN` 仅用于清空 VendorStorage SN；安全模式使用 `RSM` |

## 为什么不是“直接使用开源项目源码”

`vicharak-in/Linux_Upgrade_Tool` 的 README 明确说明 `upgrade_tool` 是 proprietary solution，
仓库内容也只有二进制、README 和版本文本，并没有 RockUSB 协议源码。因此第一阶段只能把它作为外部后端。

真正做到纯 Rust、无闭源工具依赖，还需要实现或引入以下模块：

1. libusb / WinUSB 设备发现与 RockUSB 传输；
2. Maskrom Loader 下载和 USB 重新枚举；
3. Rockchip 固件包解析、Loader IDBlock 处理与稀疏镜像写入；
4. GPT、legacy parameter、grow 分区及校验策略；
5. 多设备会话隔离。

这些属于烧录核心而不只是 UI。当前代码已把细粒度后端端口放在
`crates/application/src/ports/`，把现有 `upgrade_tool` 实现集中在
`crates/platforms/`，后续可通过依赖注入整体替换。
