# rkflash Linux 兼容性

## 支持范围

同一个由 Ubuntu 22.04 基线容器构建的 `.deb` 支持以下 amd64 桌面系统：

- Ubuntu 22.04 LTS（jammy）
- Ubuntu 24.04 LTS（noble）
- Ubuntu 26.04 LTS（resolute）

正式发布程序以 Ubuntu 22.04 和 glibc 2.35 为最低二进制兼容基线。代码不包含针对
Ubuntu 版本号的业务分支；窗口系统继续由 `eframe/winit` 的 X11、Wayland 后端适配，
文件选择由标准 XDG Desktop Portal 接口完成。

正式 `.deb` 的构建容器强制使用 Ubuntu 22.04；`RKFLASH_UBUNTU_VERSION` 不能改变这一
交付基线。构建 Debian 安装包时会自动检查主程序没有引用高于 glibc 2.35 的符号，并验证
随包 `upgrade_tool` 的 amd64/静态链接兼容性：

```bash
packaging/linux/build.sh build
```

`build.sh build`（`package` 为等价别名）在生成安装包前会自动执行该门禁。宿主机的 Ubuntu
版本不参与编译和链接，
并且交付构建使用独立的 `output/target/delivery-ubuntu-22.04/`，不会复用较新 Ubuntu
开发容器的链接缓存，因此无需为正式发布单独准备 Ubuntu 22.04 物理机或虚拟机。

## 离线包边界

应用 `.deb` 跨版本共用，但 Ubuntu 的系统运行库不能跨发行版混装。因此离线交付物必须
复用同一个 22.04 基线 `.deb`，再分别解析 22.04、24.04、26.04 的依赖。一次生成全部版本：

```bash
packaging/linux/build.sh offline-all
```

只生成单个目标版本时：

```bash
RKFLASH_UBUNTU_VERSION=22.04 packaging/linux/build.sh offline
RKFLASH_UBUNTU_VERSION=24.04 packaging/linux/build.sh offline
RKFLASH_UBUNTU_VERSION=26.04 packaging/linux/build.sh offline
```

这一区分避免在 Ubuntu 22.04 上安装 24.04/26.04 的 libc、systemd 或图形栈包。每个离线
包都会在对应版本的干净基础容器中以 `--network none` 和 `apt-get --no-download` 执行真实
安装验证；只有包内校验、APT 安装、dpkg 状态和关键文件检查全部通过，命令才成功。

本机安装使用 `packaging/linux/build.sh install`，或使用出包时与 `.deb` 一起生成的
`output/dist/install.sh`。离线包解压后使用包内 `./install.sh`。这些路径都会把
`.deb` 暂存到 `/var/tmp` 下的可遍历目录，既保留 APT 的 `_apt` 沙盒，也不要求把用户家目录
从 `0750` 放宽为全局可遍历。
