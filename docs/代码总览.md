# 代码总览与文档索引

rkflash 是一个面向 Rockchip 开发板的 **Linux（Ubuntu 桌面）原生 USB 固件烧录工具**：
界面用 `egui/eframe` 构建，后端以参数数组直接调用 Rockchip 官方闭源 `upgrade_tool`
（不经过 shell），支持设备轮询、实时日志、任务进度与中止操作，对标 Windows 平台的
RKDevTool。交付形态为 `.deb` 安装包（含按 Ubuntu 版本分别打包的离线依赖包）。

本文是整套代码文档的入口；各专题文档见文末索引。

---

## 1. 仓库结构

```text
rkflash/
├── VERSION  Makefile         # 唯一版本来源；统一构建入口
├── Cargo.toml                # Rust 工作区（Linux 与 Windows 共用），default-members = launcher
├── rust-toolchain.toml       # 固定 Rust 工具链版本
├── .cargo/config.toml        # target-dir 固定为 output/target
├── crates/                   # 通用代码，不含任何平台条件编译
│   ├── core/                 # rkflash-core：领域核心
│   ├── api/                  # rkflash-api：按功能区划分的前后端契约
│   ├── config/               # rkflash-config：配置模型 + JSON codec
│   ├── application/          # rkflash-application：service/ 实现 api，端口定义
│   ├── runtime/              # rkflash-runtime：进程执行、设备轮询、日志、持久化
│   ├── frontend/             # rkflash-frontend：egui 视图 + actions/ 动作层
│   └── launcher/             # rkflash 二进制：按目标系统选择平台包
├── platforms/                # 每个系统一个目录，互不依赖
│   ├── linux/                # upgrade_tool 适配器、Unix 宿主、桌面配置；packaging/ 构建 .deb
│   ├── windows/              # rkdeveloptool 适配器、Win32 宿主、桌面配置；packaging/ 构建安装程序
│   └── macos/                # SwiftUI 原生应用
├── third_party/              # rkdeveloptool 与 libusb 源码（Windows 与 macOS 共用）
├── assets/icons/             # 三个平台共用的图标
├── docs/                     # 技术文档（见文末索引）
├── skills/rkflash-engineering/ # AI 工程规范（SKILL.md）
└── output/  dist/            # 构建产物（不入库）
```

Linux 打包所需的 Docker 镜像、脚本、deb 资源与 `upgrade_tool` 都在 `platforms/linux/packaging/`。

## 2. Crate 依赖方向

```text
rkflash-launcher ──> rkflash-frontend ──> rkflash-api ──> rkflash-config
        │                                      ▲
        └────────> rkflash-application / rkflash-runtime ────────────┘
                          └────────────────────────> rkflash-config
```

| Crate | 职责 |
|---|---|
| `crates/api` | 前后端唯一共享契约：按功能区划分的接口（`DownloadApi`、`UpgradeApi`……）、请求类型、设备状态、执行事件、工具能力 |
| `crates/config` | 镜像/工作区可序列化模型与 JSON codec |
| `crates/core` | 平台无关核心：RKFW/RKAF 固件解析与 MD5、分区表与 parameter、芯片识别、工具输出识别、rkdeveloptool 协议与烧录工作流；不依赖界面、契约、配置或进程管理 |
| `crates/application` | 应用层；`service/` 下逐个实现 api 接口，所有系统能力经端口注入 |
| `crates/frontend` | egui 桌面交付层；只依赖 api，视图经 `actions/`（与 api 模块一一对应）调用后端 |
| `platforms/linux`、`platforms/windows` | 平台差异：烧录工具适配器、操作系统宿主、桌面界面配置与打包脚本 |
| `crates/launcher` | 唯一二进制；只装配后端与前端，不放任何业务或 UI 实现 |

装配链：`launcher::main` → `platforms::<当前平台>::create_application()`（组装根：发现工具 →
`ProcessRuntime` → 注入 8 个端口 → 构造 `FlashApplication`）与 `desktop_profile()` →
`frontend::desktop::run`。前端只见 api 接口；执行计划、命令码、适配器类型全部封在后端内部。

## 3. 核心设计原则

- **端口-适配器**：所有系统能力（进程、文件、厂商工具）经应用端口注入；
  `FlashApplication` 只协调端口，不碰 `std::fs`/`std::process`；通用执行逻辑与
  Rockchip 特殊配置分离，后续替换为 Rust 原生 RockUSB 时不需要重写页面。
- **前后端一一对应**：每个界面功能区对应一个 api 模块，请求类型在前后端共享；后端内部再统一为
  `FlashOperation` 交给平台适配器规划；Rockchip 命令码的单一权威位置是
  `platforms/linux/src/upgrade_tool.rs`。
- **安全语义**：
  - 写入/擦除/状态切换前强制确认；同一时刻只允许一个任务；**多设备拒绝执行**（防误刷）；
  - 破坏性命令（WL/RL/EL）的扇区参数双重经过 `normalize_sector` 校验；
  - 子进程参数不经过 shell；进程 HOME 隔离 + 独立进程组 + 按组 SIGKILL；
  - 不主动加载 Loader、不主动进入 Maskrom，只识别并显示当前设备模式；
  - 即使退出码为 0，也解析输出文本识别工具失败（`Fail` 等模式）。
- **构建不碰宿主**：一切构建发生在版本固定的 Docker 容器内；正式 `.deb` 固定在
  Ubuntu 22.04 基线编译（glibc 2.35 最低兼容），构建流程不调用宿主 `sudo`/`apt`/
  `cargo`/`rustup`。
- **不提交闭源二进制**：仓库只保存 `upgrade_tool` 的 SHA-256 摘要，打包时校验。

## 4. 关键运行时行为速查

| 项 | 值 |
|---|---|
| 工具发现顺序 | `RK_UPGRADE_TOOL` → exe 目录 `tools/` → CWD `tools/` → `/usr/lib/rkflash/upgrade_tool` → `PATH` → 界面手动选择 |
| 设备轮询 | 每 2 秒 `LD` 扫描，任务执行期间暂停；单次扫描 10 秒超时 |
| 刷新节奏 | 前端任务进行中 100ms / 空闲 500ms 重绘 |
| 操作日志 | 每次操作一个独立文件 `YYYYMMDD-HHMMSS-mmm.log`，默认目录 `/tmp/rkflash/log`（可用 `RKFLASH_LOG_DIR` 覆盖） |
| 工作区配置 | JSON 格式（版本 1），保存采用临时文件 + 原子 rename |
| parameter 导入 | 解析 `mtdparts=`，同目录按 `img > bin > txt` 优先级自动匹配固件 |
| 默认窗口 | 1320×860，最小 960×700，三档响应式布局 |
