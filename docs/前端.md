# 前端详解：`rkflash-frontend`

前端是基于 **egui/eframe** 的单窗口即时模式 GUI，分为“视图 + 动作层”两层。
**前端不直接访问 USB 设备、磁盘固件或烧录工具**，所有业务能力经 `rkflash-api` 的各功能区接口获得。
视图（页面、外壳、浮层）只调用动作层；动作层 `actions/<模块>.rs` 只调用同名 api 模块，
是前端唯一调用后端的地方。前端不含平台条件编译，字体、渲染器等平台差异由 `DesktopProfile` 注入。
依赖仅 4 个：`eframe`、`image`（解码内嵌
PNG 图标）、`rfd`（原生文件对话框）、`rkflash-api`。零异步运行时，全部同步 + 轮询模型。

```text
crates/frontend/src/
├── lib.rs                  # crate 入口，仅 pub mod desktop
└── desktop/
    ├── mod.rs              # run()、RkFlashApp 状态、eframe 帧循环
    ├── profile.rs          # DesktopProfile：平台注入的字体、渲染器、启动失败提示
    ├── view_model.rs        # 纯 UI 类型（可单测，无 egui 依赖），含 ConfirmedAction
    ├── actions/             # 动作层：唯一调用后端的地方，与 api 模块一一对应
    │   ├── mod.rs           # 两阶段确认：ask_confirmation / run_confirmed
    │   ├── device.rs        # ↔ DeviceApi
    │   ├── task.rs          # ↔ TaskApi（任务事件 → 界面）
    │   ├── download.rs      # ↔ DownloadApi
    │   ├── upgrade.rs       # ↔ UpgradeApi
    │   ├── advanced.rs      # ↔ AdvancedApi
    │   ├── settings.rs      # ↔ SettingsApi
    │   ├── log.rs           # ↔ LogApi
    │   └── workspace.rs     # ↔ WorkspaceApi
    ├── chrome.rs            # 顶部导航、底部状态栏、运行终端外壳
    ├── components.rs        # 通用视觉组件
    ├── layout.rs            # 响应式布局档位
    ├── overlays.rs           # 错误气泡、设备提示、确认浮层
    ├── theme.rs             # 视觉令牌 + 中文字体装配
    ├── file_dialog.rs       # rfd 对话框后台线程封装
    ├── font.rs             # 按 DesktopProfile 的候选加载中文字体
    └── pages/
        ├── download.rs      # 01 下载镜像
        ├── upgrade.rs       # 02 升级固件
        └── advanced.rs      # 03 高级功能
```

`RkFlashApp` 是唯一的状态容器；chrome/actions/overlays/pages 都是对同一结构体按职责
拆分的 `impl` 扩展，可见性用 `pub(super)` / `pub(in crate::desktop)` 控制。

## 1. 启动与帧循环：[mod.rs](../crates/frontend/src/desktop/mod.rs)

`pub fn run(application: impl FlashService + 'static, profile: DesktopProfile) -> Result<(), String>`
是前端唯一启动入口，`application` 与 `profile` 都由平台包提供：

- 按 `profile.renderers` 依次尝试渲染器，前一个创建窗口失败时换下一个；全部失败时调用
  `profile.show_startup_error`（Windows 为对话框）；

- `ViewportBuilder`：`with_app_id("rkflash")`（与 `platforms/linux/packaging/files/rkflash.desktop` 对齐，
  保证 Wayland/GNOME 任务栏图标分组正确）、标题 `rkflash`、初始 1320×860、
  最小 **960×700**（最小宽度保证布局档位都有定义）；
- 图标在编译期内嵌：`include_bytes!("../../../../assets/icons/rkflash-256.png")`；
- 失败统一映射 `启动 rkflash 图形界面失败：{error}`。

### 1.1 RkFlashApp 状态

| 字段组 | 字段 | 说明 |
|---|---|---|
| 后端 | `application: Box<dyn FlashService>`（只允许 `actions/` 访问）、`tool: ToolInfo`、`egui_ctx` | 能力端口、工具能力、供后台线程唤醒 UI |
| 页面 | `tab: AppTab` | Download / Upgrade / Advanced |
| 下载页 | `images`、`selected_image`、`reset_after_download`（默认 true） | 分区镜像队列 |
| 升级页 | `firmware_path`、`firmware_size_cache`、`no_reset_after_upgrade` | 固件与选项 |
| 高级页 | `loader_path`、`loader_storage`（0=自动 1=eMMC 2=NOR 3=NAND）、`lba_start`（默认 `0x00000000`）、`lba_count`（默认 `0x00002000`）、`lba_image_path`、`output_path`、`tool_log_directory` | LBA / Loader / 串口 / 日志 |
| 运行时 | `device_snapshot`、`logs`、`progress`、`status_text`、`follow_logs`、`logs_expanded`、`session_started_at` | 终端与状态 |
| 浮层 | `pending_action`、`error_toast`、`operation_tip`、`recognized_device_mode`、`log_persistence_error` | 确认框 / 气泡 / 提示 / 去抖 |

`new()` 流程：安装主题与中文字体 → 推送版本日志 → `load_tool_settings()` 读取工具能力、
日志目录并写工具日志 → `restore_default_images()` 填充默认分区表；无中文字体时追加
"建议安装 fonts-noto-cjk"警告。

### 1.2 帧循环 `update()`

固定顺序（顺序即面板占位顺序，决定最终视觉为：顶部导航 / 中央页面 / 运行终端 / 最底状态栏）：

1. `handle_shortcuts`（Ctrl+1/2/3 切页、Esc 关确认框）；
2. `refresh_devices` 与 `process_task_events`（轮询后端）；
3. `poll_file_dialogs`（收割后台对话框结果）;
4. `render_header`（顶部，高 78）→ `render_status`（最底，高 42）→ `render_logs`
   （状态栏上方，可伸缩）→ `CentralPanel`（按 `tab` 分派页面；
   **`pending_action` 存在时 `ui.disable()`，形成真正模态**）；
5. 依次渲染错误气泡 / 设备提示 / 确认模态三个浮层；
6. `request_repaint_after`：**任务进行中 100ms，空闲 500ms** —— 前端的刷新节奏即轮询频率。

### 1.3 轮询协议：事件 → UI 映射

每帧 `refresh_devices()` 有新快照才覆盖（先做模式提示去抖），`drain_task_events()` 取回任务事件。
事件映射（`actions/task.rs`）：

| `ExecutionEvent` | UI 反应 |
|---|---|
| `TaskStarted { name, steps }` | 进度归零；状态栏"正在执行：{name}"；日志输出操作日志路径与步骤数 |
| `StepStarted { index, total, label, command }` | 状态栏 `[{index}/{total}] {label}`；Command 级日志 `$ {command}` |
| `Output { text, stderr }` | 级别启发式：stderr 或含 fail/error → Error；含 success / ` ok.` 结尾 → Success；否则 Info |
| `Progress(v)` | 更新进度条 |
| `TaskFinished { success, cancelled, .. }` | 成功 → 进度 1.0 + Success；中止 → Warning；失败 → Error 日志 + **弹出错误气泡** |

`push_log` **先落盘再入内存**（`append_operation_log` 携带级别标签）；持久化失败插入
Error 并按消息去重（同一错误只提示一次）；内存日志超 2000 条时一次性丢弃最旧 500 条。

## 2. 视图模型：[view_model.rs](../crates/frontend/src/desktop/view_model.rs)

纯 UI 类型，无 egui 依赖，含单元测试：

- `AppTab`：三个页面枚举。
- `PendingAction { title, detail, danger, action: ConfirmedAction }`：待确认操作载体，
  `danger` 决定确认框配色（红/黄）。`ConfirmedAction` 的每个变体对应一个需要确认的 api 执行函数。
- `LogLevel`（Info/Success/Warning/Error/Command）与 `label()` →
  `INFO/SUCCESS/WARN/ERROR/COMMAND`（落盘日志级别标签）；`LogEntry.elapsed_label()` 格式
  `+分:秒.毫秒`。
- `ErrorToast`：**15 秒**自动消失，带倒计时条。
- `DeviceMode`（Maskrom/Loader）：`from_label` 大小写不敏感识别；
  `guidance()` 提示文案体现产品红线——Maskrom：
  *rkflash 只显示当前状态，不会主动加载 Loader 或切换模式*。
- `OperationTip`：**10 秒**设备模式提示。

## 3. 动作层：[actions/](../crates/frontend/src/desktop/actions)

视图与 api 之间的唯一桥梁。每个文件只调用同名 api 模块的接口，架构检查禁止视图直接调用 api。

### 3.1 两阶段确认

改变设备的操作统一走：

```text
request_xxx()                       # actions/<模块>.rs，由页面按钮调用
  → application.check_xxx(&request) # 同步校验，失败直接 report_error，不弹框
  → pending_action = Some(ConfirmedAction::Xxx(request))
  → 确认模态（用户点"确认执行"）
  → run_confirmed() → xxx(request) → application.xxx(request)   # 异步启动
```

### 3.2 完整映射总表

| UI 动作 | 动作层 | api 接口 | 需确认 | danger |
|---|---|---|---|---|
| 开始下载 | `request_download` | `DownloadApi::download_images` | 是 | 是 |
| 设备分区表 | `read_partition_table` | `DownloadApi::read_partition_table` | 否 | — |
| 加载 parameter | `import_parameter` | `DownloadApi::import_parameter` | 否 | — |
| 开始升级 | `request_upgrade_firmware` | `UpgradeApi::upgrade_firmware` | 是 | 是 |
| 擦除 Flash | `request_erase_flash` | `UpgradeApi::erase_flash` | 是 | 是 |
| 8 个查询按钮 | `query_device` | `AdvancedApi::query_device` | 否 | — |
| 重启设备 / 重置 USB 管道 | `request_control_device` | `AdvancedApi::control_device` | 否 | — |
| 切换存储 / 清空序列号 | `request_control_device` | `AdvancedApi::control_device` | 是 | 否 |
| 升级 Loader | `request_upgrade_loader` | `AdvancedApi::upgrade_loader` | 是 | 是 |
| 读取 LBA | `read_lba` | `AdvancedApi::read_lba` | 否 | — |
| 写入 / 擦除 LBA | `request_write_lba` / `request_erase_lba` | `AdvancedApi::write_lba` / `erase_lba` | 是 | 是 |
| 开始导出串口日志 | `export_serial_log` | `AdvancedApi::export_serial_log` | 否 | — |
| 选择工具 / 日志目录 | `set_tool_path` / `set_tool_log_directory` | `SettingsApi` | 否 | — |
| 导入 / 导出配置 | `load_workspace` / `save_workspace` | `WorkspaceApi` | 否 | — |
| 停止任务 | `cancel_task` | `TaskApi::cancel_task` | 否 | — |
| 解包固件 | 永久禁用占位 | — | — | — |

按钮是否可用由 `ToolInfo` 决定（例如 Windows 版的 rkdeveloptool 不支持串口日志与 SPI NAND），
前端不按工具名分支。

## 4. 外壳：[chrome.rs](../crates/frontend/src/desktop/chrome.rs)

- **顶部**：品牌区（RK 徽标 + "RK FLASH STUDIO"）+ 三个页签（选中态带 2px 强调色
  底线，hover 提示 `Ctrl+N`）+ 工具状态按钮（`● 工具就绪` 绿 / `○ 选择工具` 黄；
  **每帧只查一次** `tool_path()`，hover 显示完整路径）。
- **底部状态栏**（42px）：设备指示（三态：`未发现设备` / `Loader · VID../PID../位置..` /
  `发现 {n} 台设备，请仅保留目标设备`——多设备是显式警告，前端**永不自动选择目标**）、
  状态文本、任务进度条、版本号；`停止任务` 按钮**只在任务进行中才加入 UI**，
  点击调用 `cancel()` 并提示"正在请求停止当前任务……"（协作式取消，真正结束由
  `TaskFinished{cancelled:true}` 驱动）。
- **运行终端**（可伸缩面板）：展开默认高 176（范围 124–320）；头部显示
  记录状态徽章、事件计数、磁盘操作日志文件名（hover 完整路径）；控件：收起/展开、
  `清屏`（仅清内存，hover 明示不删磁盘日志）、`跟随输出` 复选框。正文用
  `ScrollArea::show_rows` **逐行虚拟化**（固定行高 21，只布局视口内行），每行 =
  相对时间戳 + 级别 tag + 正文。
- `page_heading`：三页共用页头，含设备摘要块。

## 7. 三个页面：[pages/](../crates/frontend/src/desktop/pages/)

### 7.1 download.rs —— 01 下载镜像

- **工具栏**：`加载参数`（parameter.txt）、`导入配置` / `导出配置`（工作区 JSON，
  导出默认名 `flash-layout.rkflash.json`）、`设备分区表`（Query）、`恢复默认`
  （后端默认分区表）、`清空路径`（红字）。
- **镜像写入队列**（Grid 表格，striped 6 列）：每行 = 启用复选框、扇区地址输入（112 宽）、
  分区名（`SelectableLabel`，**点击即选中该行**，配合上移/下移）、镜像路径输入、
  `选择`（过滤器 img/bin/txt）、`删除`。
- **下载控制台**（310px 侧栏 / 窄屏紧凑版）：指标（下载项/已启用/路径就绪）、
  `+ 添加` / `上移` / `下移`、`完成后重启设备` 复选框、就绪提示（绿/黄）、
  `开始下载`（confirm，danger，文案警告错误镜像可能导致设备无法启动）。

### 7.2 upgrade.rs —— 02 升级固件

始终在 ScrollArea 中渲染，两张卡：

1. **选择统一固件**：路径输入（**支持直接粘贴绝对路径**）+ 选择按钮（过滤器 img）；
   指标条：文件类型（`Rockchip IMG` / `未知格式`）、文件大小（**按路径缓存**
   `file_size` 结果，避免每帧 stat）、校验方式（`任务启动时校验`——前端不做格式校验，
   交给 upgrade_tool）。
2. **升级流程**：三步指引（连接/校验/写入）+ `-noreset` 复选框 +
   `开始升级` / `擦除 Flash`（均 confirm + danger）、`解包固件`（永久禁用占位）。

### 7.3 advanced.rs —— 03 高级功能

宽屏两列、窄屏堆叠，六张卡片：

1. **设备信息**：8 个只读查询按钮（FlashId/FlashInfo/ChipInfo/Capability/分区表/
   USB 序列号/安全模式/测试）。
2. **设备控制**：重启（无确认）、切换存储（确认）、清空序列号（确认）、重置 USB 管道（无确认）。
3. **Loader 升级**：路径选择（bin/img）+ 存储下拉（自动/eMMC/SPI NOR/SPI NAND）+
   升级按钮（confirm，文案警告写错 Loader 可能只能 Maskrom 恢复）。
4. **LBA 扇区操作**（单位 512 字节扇区）：起始/数量输入 + 路径；
   `读取 LBA` —— **路径为空时先弹保存对话框（默认名 `flash-export.img`），选定后自动
   开始读取**（两步交互合一）；`写入 LBA` / `擦除 LBA`（均 confirm + danger）。
5. **串口日志导出**：输出路径（保存对话框，默认 `rockchip-serial.log`）+ 直接导出。
6. **工具运行日志**：状态徽章（正在记录/归档就绪）、当前日志文件名、
   日志目录输入 + 选择目录 + `应用位置`（**任务进行中禁用**并 hover 说明）；
   页脚注明默认目录 `/tmp/rkflash/log` 与 `RKFLASH_LOG_DIR` 覆盖。

## 8. 主题与中文字体

### 8.1 [theme.rs](../crates/frontend/src/desktop/theme.rs)

全部颜色集中为视觉令牌常量（深色控制台风格）：
`CANVAS/SURFACE_DEEP/PANEL/PANEL_RAISED/PANEL_HOVER/BORDER/BORDER_SOFT/TEXT/MUTED/
ACCENT(WARNING/SUCCESS/DANGER) 系`。`install()` 强制 dark mode、映射 egui 四态
widget 样式、设置字号表（Heading 24 / Body 14 / Monospace 13 / Button 14 / Small 12），
末尾装配中文字体并**返回字体是否可用**（驱动启动警告）。

### 8.2 [font.rs](../crates/frontend/src/desktop/font.rs)

`load_cjk_font(candidates)` 按 `DesktopProfile::cjk_fonts` 的顺序探测系统中文字体并整读入内存。
候选列表由平台包提供：

- Linux（`platforms/linux/src/desktop.rs`）：Noto CJK `.ttc`（**face_index = 2**，简体中文字形位于索引 2）、
  `NotoSansCJKsc-Regular.otf`、文泉驿、DroidSansFallbackFull、AR PL uming，以及供 macOS 开发预览的苹方；
- Windows（`platforms/windows/src/desktop.rs`）：微软雅黑、黑体。

注册策略：**Proportional 族 insert(0)**（CJK 字形优先于内置字体）+ **Monospace 族
追加**（ASCII 仍用原生等宽字形，中文走 CJK 回退，终端中英文混排观感正确）。
找不到字体不静默降级，启动日志给出"安装 fonts-noto-cjk"建议。

## 9. 文件对话框：[file_dialog.rs](../crates/frontend/src/desktop/file_dialog.rs)

rfd 同步 API 在 xdg-portal 后端上会阻塞等待 DBus 往返，**直接在 UI 线程调用会冻结
界面循环**。因此统一在工作线程打开对话框：创建 mpsc 通道 → 后台线程执行
pick/save → `request_repaint()` 唤醒 UI → 每帧 `poll_file_dialogs` 收割结果
（逆序移除，用户取消静默）。支持多个对话框并发挂起。

## 10. 值得注意的工程细节

- `is_task_running()` 全局互斥一切操作按钮；单任务模型贯穿前后端。
- 执行函数只负责启动，结果全部经后续帧的 `ExecutionEvent` 流回流。
- UI 日志与磁盘操作日志**双写**；"清屏"只清内存。
- 确认模态先调用 `check_*`，校验失败不弹框直接报错，避免无意义的确认。
- 视图模型与布局模块为纯逻辑层，含单元测试（模式识别、Toast、时间格式化、布局三档）。
