# 契约层详解：`rkflash-api` 与 `rkflash-config`

本文覆盖两个最底层、被前后端共同依赖的 crate：

- [crates/api](../crates/api)：前后端唯一共享契约（按功能区划分的接口与类型）。
- [crates/config](../crates/config)：可序列化配置模型与 JSON 编解码。

两者的硬性边界：**不依赖 GUI、进程、文件系统、设备访问或任何具体适配器**，
依赖方向上只允许 `api → config`。构建时的架构门禁（`platforms/linux/packaging/build.sh architecture`）会持续检查这两条约束。

```text
rkflash-frontend ──┐
                   ├──> rkflash-api ──> rkflash-config
rkflash-application / rkflash-runtime ───┘
```

---

## 1. `rkflash-api`（crates/api/src/）

api 按前端功能区分模块，每个模块包含该功能区的请求类型和一个接口 trait。
前端 `desktop/actions/<模块>.rs` 只调用同名接口，应用层 `service/<模块>.rs` 实现同名接口
（对应关系见[分层架构](分层架构.md#前后端一一对应)）。`FlashService` 是全部接口的组合，
任何实现了全部接口的类型自动满足，前端只持有 `Box<dyn FlashService>`。

所有错误统一为 `Result<_, String>`（中文用户可读消息）。

### 1.1 设备状态：[device.rs](../crates/api/src/device.rs) · `DeviceApi`

| 类型 | 说明 |
|---|---|
| `DeviceInfo` | `number` / `vid` / `pid` / `location` / `mode` / `serial`，全部为 `String` |
| `DeviceSnapshot` | `devices: Vec<DeviceInfo>`、`error: Option<String>`；扫描失败时设备列表为空并给出原因 |
| `StorageType` | `Auto`、`Emmc`、`SpiNor`、`SpiNand`；`ALL` 与 `name()` 供界面列举 |

```rust
fn refresh_devices(&mut self) -> Option<DeviceSnapshot>;   // None：本轮没有新结果
```

### 1.2 任务：[task.rs](../crates/api/src/task.rs) · `TaskApi`

`ExecutionEvent` 五个变体构成任务完整生命周期，不暴露执行计划与适配器细节：

| 变体 | 载荷 | 说明 |
|---|---|---|
| `TaskStarted` | `name, steps` | 任务开始，`steps` 为计划命令数 |
| `StepStarted` | `index, total, label, command` | 单条命令开始；`command` 仅用于展示 |
| `Output` | `text, stderr` | 逐行工具输出，已剥离终端控制序列 |
| `Progress` | `f32` | 0.0–1.0 整体进度 |
| `TaskFinished` | `name, success, cancelled, message` | 任务结束；`cancelled` 区分用户中止与真实失败 |

```rust
fn drain_task_events(&self) -> Vec<ExecutionEvent>;
fn is_task_running(&self) -> bool;
fn cancel_task(&self);
```

### 1.3 下载镜像页：[download.rs](../crates/api/src/download.rs) · `DownloadApi`

```rust
fn default_images(&self) -> Vec<ImageEntry>;
fn import_parameter(&self, path: &Path) -> Result<Vec<ImageEntry>, String>;
fn read_partition_table(&self) -> Result<(), String>;
fn check_download(&self, request: &DownloadRequest) -> Result<(), String>;
fn download_images(&self, request: DownloadRequest) -> Result<(), String>;
```

`DownloadRequest { images, reset_after }`。

### 1.4 升级固件页：[upgrade.rs](../crates/api/src/upgrade.rs) · `UpgradeApi`

```rust
fn firmware_size(&self, path: &Path) -> Result<u64, String>;
fn check_upgrade_firmware(&self, request: &FirmwareUpgradeRequest) -> Result<(), String>;
fn upgrade_firmware(&self, request: FirmwareUpgradeRequest) -> Result<(), String>;
fn check_erase_flash(&self, request: &EraseFlashRequest) -> Result<(), String>;
fn erase_flash(&self, request: EraseFlashRequest) -> Result<(), String>;
```

`FirmwareUpgradeRequest { firmware, no_reset, storage }`：`storage` 只在
`ToolInfo::firmware_storages` 非空时生效。`EraseFlashRequest { firmware }`。

### 1.5 高级功能页：[advanced.rs](../crates/api/src/advanced.rs) · `AdvancedApi`

- `DeviceQuery`：`FlashId`、`FlashInfo`、`ChipInfo`、`Capability`、`PartitionTable`、
  `UsbSerialNumber`、`SecureMode`、`TestDevice`。
- `DeviceControl`：`Reboot`、`SwitchStorage`、`ClearSerial`、`ResetUsbPipe`。
- 两个枚举都提供 `ALL` 与 `name()`（中文操作名，界面与日志共用）。

```rust
fn query_device(&self, query: DeviceQuery) -> Result<(), String>;
fn check_control_device(&self, control: DeviceControl) -> Result<(), String>;
fn control_device(&self, control: DeviceControl) -> Result<(), String>;
fn check_upgrade_loader(&self, request: &LoaderUpgradeRequest) -> Result<(), String>;
fn upgrade_loader(&self, request: LoaderUpgradeRequest) -> Result<(), String>;
fn read_lba(&self, request: LbaReadRequest) -> Result<(), String>;
fn check_write_lba(&self, request: &LbaWriteRequest) -> Result<(), String>;
fn write_lba(&self, request: LbaWriteRequest) -> Result<(), String>;
fn check_erase_lba(&self, request: &LbaEraseRequest) -> Result<(), String>;
fn erase_lba(&self, request: LbaEraseRequest) -> Result<(), String>;
fn export_serial_log(&self, request: SerialLogRequest) -> Result<(), String>;
```

LBA 请求中的 `start` / `count` 为字符串，允许十进制或 `0x` 十六进制文本，由后端统一校验。

### 1.6 烧录工具设置：[settings.rs](../crates/api/src/settings.rs) · `SettingsApi`

`ToolInfo` 描述当前平台烧录工具的名称与能力。前端据此显示或禁用入口，不按工具名分支：

| 字段 | 说明 |
|---|---|
| `name` | 界面显示的工具名（upgrade_tool 或 rkdeveloptool） |
| `queries` / `controls` | 支持的设备查询与控制 |
| `loader_storages` | 升级 Loader 可选的存储 |
| `firmware_storages` | 整包升级前可选的存储；为空表示工具自动识别，不显示该选项 |
| `serial_log` | 是否支持导出串口日志 |

```rust
fn tool_info(&self) -> ToolInfo;
fn tool_path(&self) -> Option<PathBuf>;
fn set_tool_path(&self, path: PathBuf) -> Result<(), String>;
fn tool_log_directory(&self) -> PathBuf;
fn set_tool_log_directory(&self, path: PathBuf) -> Result<(), String>;
```

### 1.7 操作日志：[log.rs](../crates/api/src/log.rs) · `LogApi`

```rust
fn operation_log_path(&self) -> Option<PathBuf>;   // 当前任务日志，其次最近一次任务的日志
fn append_operation_log(&self, level: &str, text: &str) -> Result<(), String>;
```

### 1.8 工作区：[workspace.rs](../crates/api/src/workspace.rs) · `WorkspaceApi`

```rust
fn load_workspace(&self, path: &Path) -> Result<WorkspaceConfig, String>;
fn save_workspace(&self, path: &Path, config: &WorkspaceConfig) -> Result<(), String>;
```

同时 re-export `rkflash-config` 的 `ImageEntry`、`WorkspaceConfig`、`WORKSPACE_FORMAT_VERSION`。

### 1.9 设计要点

- 执行函数是**异步启动**：校验通过后立即返回，进度经 `drain_task_events()` 送达。
- 改变设备的操作成对提供 `check_*`：界面先校验再弹确认框，避免用户确认一个注定失败的操作。
  执行函数内部会再校验一次，不依赖前端是否调用过 `check_*`。
- 后端内部把各请求统一转换为应用层的 `FlashOperation` 交给平台适配器规划；
  `FlashOperation`、执行计划与命令码对前端不可见。

## 2. `rkflash-config`（crates/config/src/）

### 2.1 配置模型：[model.rs](../crates/config/src/model.rs)

`WORKSPACE_FORMAT_VERSION: u32 = 1`——工作区 JSON 的当前格式版本。

`ImageEntry`（可序列化）：

| 字段 | 类型 | 说明 |
|---|---|---|
| `enabled` | `bool` | 是否勾选下载 |
| `address` | `String` | 起始扇区，十进制或 `0x` 十六进制文本，**原样保存**不做规范化 |
| `name` | `String` | 分区名，可带冒号后缀（如 `rootfs:grow`） |
| `path` | `String` | 镜像文件路径；`ImageEntry::new` 构造时置空 |

注意 `path` 是 `String` 而各请求中使用 `PathBuf`，转换发生在应用层。

`WorkspaceConfig`（可序列化）：

| 字段 | 类型 | 说明 |
|---|---|---|
| `format_version` | `u32` | 写入时由后端置为当前版本 |
| `images` | `Vec<ImageEntry>` | 下载镜像清单 |
| `firmware_path` | `String` | update.img 固件路径 |
| `loader_path` | `String` | MiniLoaderAll.bin 路径 |
| `reset_after_download` | `bool` | 下载完成后重启 |
| `no_reset_after_upgrade` | `bool` | 升级后不重启（对应 `-noreset`） |

### 2.2 JSON 编解码：[codec.rs](../crates/config/src/codec.rs)

```rust
pub fn decode_workspace(text: &str) -> Result<WorkspaceConfig, serde_json::Error>;
pub fn encode_workspace(config: &WorkspaceConfig) -> Result<String, serde_json::Error>;
```

- `decode_workspace` 只做 `serde_json::from_str`，**不做版本检查**——版本校验由
  `FlashApplication::load_workspace` 负责，codec 保持纯编解码职责。
- `encode_workspace` 使用 `to_string_pretty`，落盘为带缩进的可读 JSON。
- 单元测试 `round_trips_workspace_configuration` 保证编码-解码往返一致。

## 3. 扩展约定

- 新增功能时：在对应功能区的 api 模块增加请求类型与接口函数，在应用层 `service/` 同名模块实现，
  在前端 `actions/` 同名模块调用；需要新命令时再在 `FlashOperation` 与平台适配器中实现。
  前端不接触命令码。
- 契约类型只增不破坏性修改；确需演进工作区格式时递增 `WORKSPACE_FORMAT_VERSION`
  并在后端加载处给出明确的中文版本错误。
